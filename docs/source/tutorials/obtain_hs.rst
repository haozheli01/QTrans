===============================================
Generation of Hamiltonian and Overlap Matrices
===============================================

In this tutorial, we will show how to obtain the Hamiltonian and overlap matrices
from other software, and how to convert them into the format required by **QTrans**.
Normally, **QTrans** reads the Hamiltonian and overlap matrices from graph data (``.npz`` files).
Additionally, it can also read ``.npy`` files containing predicted Hamiltonians generated by **HamGNN**.

Based on DFT Calculations
------------------------------------------

1. DFT Calculations Performed with OpenMX
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

This tutorial is located in ``tutorials/Al/graph_pack/``. 
Reference outputs are provided in ``tutorials/Al/graph_pack/ref/`` , 
which can be used to compare with your own results to verify that **QTrans** is running correctly.

Firstly, we need to run **OpenMX** to perform the DFT calculation using the following commands:

.. code-block:: none

    [user]$ cd tutorials/Al/graph_pack/DFT/ && ls
    openmx_Al.dat
    [user]$ mpirun -np 8 openmx openmx_Al.dat > openmx_scf.out

Once the calculation completes successfully, you will find the files ``{System.Name}.scfout`` and ``{System.Name}.out``
in the current directory. Then, we can pack the data into graph data format. We go back to the parent directory.

.. code-block:: none

    [user]$ cd ../ && ls
    DFT/  input_graph.yaml  ref/

Now, we need to configure the input file ``input_graph.yaml``.
The paths specified in ``software_path`` block depend on the locations of your DFT softwares.
And you can set :ref:`nao_max <prep_nao_max>` and :ref:`DFT_software <prep_DFT_software>` according to your own DFT calculations.
In order to pack the self-consistent Hamiltonian, in the ``graph_pack`` block,
we need to set the parameter :ref:`HSout_filename <prep_HSout_filename>`
to ``{System.Name}.scfout`` and :ref:`vbout_filename <prep_vbout_filename>` to ``{System.Name}.out``.
We set :ref:`data_folder <prep_data_folder>` to ``./DFT/``.
Alternatively, you can set it to ``./*/``.
In this case, the program will use function ``glob.glob()`` to match all folders in the current directory,
and automatically skip those that do not contain both ``{System.Name}.scfout`` and ``{System.Name}.out``.
The parameter :ref:`converge_step_ratio <prep_converge_step_ratio>` is set to be ``0.9``,
which is appropriate for our system and ensures that only well-converged results are included.

If you want to include the non-self-consistent contribution of the Hamiltonian in the graph data,
please execute the following command as well:

.. code-block:: none

    [user]$ cd DFT/
    [user]$ mpirun -np 8 openmx_postprocess openmx_Al.dat > openmx_nonscf.out

The executable ``openmx_postprocess`` can be downloaded from the `HamGNN repository <https://github.com/QuantumLab-ZY/HamGNN/>`_.
After completion, you will find the file ``overlap.scfout`` in the current directory.
To include the non-self-consistent part of the Hamiltonian,
set :ref:`nonscf_filename <prep_nonscf_filename>` to ``overlap.scfout``.

With the ``input_graph.yaml`` file configured,
you can now execute the following command to generate the graph data:

.. code-block:: none

    [user]$ QTrans_prep --config input_graph.yaml > graph_pack.out

After the task completes successfully, the file ``graph_data_QTrans.npz`` will be generated.
It contains the Hamiltonian and overlap matrices, which can be directly used by **QTrans**.

.. warning::

    During execution, **QTrans** temporarily creates a file named ``HS.json`` in each folder matched by :ref:`data_folder <prep_data_folder>`.
    The file will be automatically removed once the program finishes running.
    To avoid conflicts, please make sure that no ``HS.json`` files already exist in those folders.

Based on HamGNN Prediction
-------------------------------

This tutorial is located in ``tutorials/Al/predict_HamGNN/``. 
Reference outputs are provided in ``tutorials/Al/predict_HamGNN/ref/`` , 
which can be used to compare with your own results to verify that **QTrans** is running correctly.

We can also predict the Hamiltonian using **HamGNN**.
As an example, we use the universal model :cite:`zhongZhongUniversalMachineLearning2024` to predict the Hamiltonian of aluminum.
The universal model can be downloaded in `Zhong, Y. Zenodo <https://doi.org/10.5281/zenodo.10827117>`_.

Here, we provide a concise guide to the process.

Firstly, enter the corresponding folder:

.. code-block:: none

    [user]$ cd tutorials/Al/predict_HamGNN/DFT/ && ls
    input_graph.yaml  QTepc-0.dat  QTepc-1.dat  QTepc-2.dat  QTepc-3.dat

Actually, these four ``**.dat`` files are **OpenMX** input files of four different supercells 
generated by ``grad-epc`` mode of **QTrans**.
Unlike the procedure of extracting the Hamiltonian from a self-consistent calculation,
predicting it with **HamGNN** only requires the non-self-consistent part of Hamiltonian.
So, we need to obtain the non-self-consistent part of Hamiltonian using ``openmx_postprocess``:

.. code-block:: none
    
    [user]$ for i in {0..3}
    > do
    > mkdir ./${i}
    > cd ./${i}
    > mv ../QTepc_0.dat ./openmx.dat
    > mpirun -np 8 openmx_postprocess openmx.dat > openmx_nonscf.out
    > cd ../
    > done

After completion, you will find the file ``overlap.scfout`` in the four new folders.
Next, we need to configure the input file ``input_graph.yaml`` for QTrans to pack the graph data for these four supercells.
The paths specified in the ``software_path`` block should correspond to the locations of your DFT softwares.
Since the universal model is based on ``openmx_26`` basis, we set :ref:`DFT_software <prep_DFT_software>` to ``openmx``,
and :ref:`nao_max <prep_nao_max>` to ``26``.
To pack only the non-self-consistent part of the Hamiltonian, we set :ref:`HSout_filename <prep_HSout_filename>` to ``None``,
:ref:`nonscf_filename <prep_nonscf_filename>` to ``overlap.scfout`` and :ref:`stdin_filename <prep_stdin_filename>` to ``openmx.dat``.
As mentioned earlier, we set :ref:`data_folder <prep_data_folder>` to ``./*/``.

With the ``input_graph.yaml`` file configured,
you can now execute the following command to generate the graph data:

.. code-block:: none

    [user]$ QTrans_prep --config input_graph.yaml > graph_pack.out

After the task completes successfully, the file ``graph_data_QTrans.npz`` will be generated.
We rename it to ``graph_data.npz`` as required by **HamGNN**.
Next, we need to prepare the **HamGNN** input file ``HamGNN_config.yaml``, and run the following command:

.. code-block:: none

    [user]$ cd ../predict/ && ls
    HamGNN_config.yaml
    [user]$ HamGNN2.0 --config HamGNN_config.yaml > HamGNN_test.out

More details on how to use **HamGNN** can be found in the `HamGNN repository <https://github.com/QuantumLab-ZY/HamGNN/>`_.
After the task completes, the file ``prediction_Hamiltonian.npy`` will be generated inside the ``version_0/`` directory.
This file contains the predicted Hamiltonian and can be directly used by **QTrans**.
